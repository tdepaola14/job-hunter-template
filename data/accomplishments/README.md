# Accomplishments

One file per experience. This is where the substance of every resume comes from.

An "accomplishment" is any real thing you did that a resume could mention: a job,
an internship, a research role, a class project, a personal build, a leadership
role. One file each, kebab-case filename, for example
`campus_shuttle_dashboard.md`.

## How files get here

Run `/add-accomplishment`. The skill interviews you and writes the file in the
right structure. Writing one by hand works too; copy the shape from
[`templates/EXAMPLE-accomplishment.md`](../../templates/EXAMPLE-accomplishment.md).

That example is fictional and deliberately lives outside `data/`, so nothing in
it can ever be pulled into a real document. It is a format reference only.

## How many you need

Two or three is enough to build a first resume. Six or more makes tailoring
genuinely good, because the scoring step then has real choices to make between
experiences instead of using everything it has.

## What makes a file useful later

The resume-building skills read the **Resume Bullet Candidates** and the **STAR
Breakdown** most often, and `interview-prep` reads the STAR detail closely. A
thin file produces thin bullets. Specifics you record once get reused across
every application you ever send.

Record real numbers only. If something was never measured, the file should say
so plainly. That honesty is load-bearing: an interviewer who asks "how do you
know it was 30% faster?" needs you to have a true answer.
